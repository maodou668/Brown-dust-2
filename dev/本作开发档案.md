## 2. 系统玩法实例

### 服装系统 COSTUMES（本作核心收集单位，`js/costumes.js`）
- **服装 = 唯一收集单位**：每套服装 = 自己的属性 + 专属招式 + 外观（元素/配色）。角色 = 拥有的服装集合；穿哪套用哪套属性。招募只抽服装，抽到即拥有对应角色。
- **每角色 2 套服装**：初始服装（`base_<char>`）+ 额外服装（`ALTS` 里定义）。
- **每套服装 = 2 专属技（1 便宜节奏技 + 1 大招）**：`buildKits()` 的 `KIT` 表写入。角色共 2 套 = 5 技（普攻+4），分属两套。
- 🔺 **出战服装制（BD2，v209）**：`Game.battleSkills(owned)` 只返回**当前出战服装**的 2 技 + 普攻 = **每场 3 技**（不再把两套技能都塞进一场）。要用另一套的技能须把那套设为出战服装。出战服装因此统一决定 **外观 + 属性 + 元素 + 技能 kit**（避免"上霜华却放火技、施法动作对不上"）。
- 🔺 **换装轮转 combo（BD2，v210）**：战斗中放完**当前服装的 2 个技能**后，下回合（SP 够放下一套时）**自动轮转到下一套服装**——立绘/元素/配色/招式整套换；放完再轮，循环（2 套 A↔B，3 套 A→B→C→A）。实现：`Combatant.costumeRing`(出战服装排首) + `Battle.maybeRotateCostume(c)`(回合开始判轮转，`beginTurn` 调用)；`canUseSkill` 锁住本套已放过的技(`c.spent`)逼你攒 SP 换套；轮转后新套冷却清零、`spent` 清空、`beginTurn` 飘「🎽 换装」提示。**属性(atk/def/maxHp)暂不随轮转变**(只换外观/元素/技能，避免 HP 中途跳变)。
  🔺 **全 64 技能互不重复、无职业通用技**（`costumes.js` 顶部注释与 `buildKits` 已废弃「职业通用技」；`data.js > CHARACTERS[].skills` 里旧技能为历史死数据，实战不可达，校验不计入）。
- **稀有度缺口补偿**：服装稀有度高于角色基础稀有度时，`costumes.js` 按 `O_MULT/S_MULT` 把属性/成长抬到服装应有档位（4★ 服装真有 4★ 预算，不虚低）。
- **初始服装招牌技**：`BASE_SIG` 显式指定 16 个互不重复的招牌技（见 §3 表）。
- **出战服装 = 显示总开关（v207 战斗 / v208 地图）**：`owned.activeCostume` 决定属性/元素/招式 + **所有 sprite 渲染**。切换入口：编队/佣兵→点角色→详情弹窗「出战服装」区（`Game.switchCostume`）。渲染解析：战斗 `BattleUI.spriteKey`、地图 `World._spriteKey`，均"服装有整套 field 就用、否则回落 charId"。✅ **菜单半身像也随出战服装（v216）**：`UI.charAvatar(charId, costumeId?)` 未显式传服装时自动按 roster 的 activeCostume 解析，服装定义带 `portrait` 字段（costumes.js ALTS）则优先显示，无则回退基础半身像；服装图鉴/招募结果/自选池显式传服装 id；roster 卡片/大图预览的元素徽章·稀有度·底色也随出战服装（activeCostumeDef）；ArtLab 看立绘同步；预加载把所有服装 portrait 纳入 preloadAssets。已有专属半身像：霜华/圣盾/圣骑士（双重锁法生成，存 `ui/portraits/<costumeId>.png` + 全候选归档 `_candidates/`）。

### 抽卡（`js/data.js > GACHA`）
- 每抽消耗宝石 **100**；概率 `{5★:0.03, 4★:0.12, 3★:0.85}`。
- 池：5★ `lecliss/justia/seir/refithea/rigenette/olstein`；4★ `rou/helena/diana/garcia/glacia/liatris`；3★ `teried/lia/mina/loen`。
- 90 抽软保底（见 ROADMAP，spark/希望之粉保底为后续规划）。

### 战斗（`js/battle.js`）
- 回合制、基于速度的行动顺序；SP 充能、暴击、护盾、增益/减益。
- **元素克制**：火>风>地>水>火，光↔暗（克制 1.3×）。
- **元素反应**（`data.js > REACTIONS`）：我方异色接力命中触发反应爆发——蒸发(fire+water,0.85)/助燃(fire+wind)/熔岩(earth+fire,破防)/冰封(water+wind,冻结)/泥泞/沙暴/湮灭(dark+light,1.10)；其余异色保底「元素紊乱」0.40。
- 站位：前/中/后三段（`ENEMY_TIER`），前排保护生效。
- 探索：斜俯视 45° 等距引导式章节推进（`js/world.js`）。

### 养成（`js/game.js`、`js/gear.js`）
- 等级 + 通用装备 + 专属武器 EX gear（词条/稀有度）。装备属性在 `game.js > computeStats` 计入战斗。

## 3. 数值实例

数值模型方法见《说明书·数值章》；本作具体参数带与上限如下。

### 剧情战难度定值（2026-07 实测锁定，改动必须重跑模拟）
- **新手真实入场状态**：新档 roster=teried+mina 双人 Lv1，`team` 默认为空（玩家须编队）；序章 reward exp **80**（升级线 `expToNext(1)=62`，打完必升 Lv2）。
- **sc_prologue**：mod `atkMul 0.65 / hpMul 0.55` → 新档双人 Lv1 胜率 ~85%，4-6 回合。
- **sc_chapter1**：wolf Lv3 ×2 + dark_mage Lv4，mod **`atkMul 0.6 / hpMul 0.5`**，exp 90 → 双人 Lv2 胜率 100%（8 回合）、双人 Lv1（老档兜底）65%。⚠️ 教训：原 0.85/0.8 时双人 Lv1-6 胜率 0%（Lv5 才 82%），是新手死墙——**剧情战调难度必须用"玩家到这一步的真实阵容/等级"模拟，不能拿推荐等级队测**。
- 模拟工具：`scripts/playtest.js`（推荐等级队全关卡）；剧情线新手路径用同款 vm harness 换真实入场阵容（序章→领奖→第一章全链路）。

### 技能预算（`js/balance.js` + `costumes.js > SIG_SPECS / KIT`）
- 只写规格（`sp/target/effect/附带效果`），威力由 `Balance.make()` 反解；`make()` 天然平衡分 = 1.00。
- **校验带**：每个实战可达技能 `|score-1| ≤ 0.18`。
- `target` 取值：`enemySingle/enemyRow/enemyAll/allySingle/allyAll/self`；`effect`：`damage/heal/shield/buffAtk/buffDef`。

### 角色/服装属性双轴预算（`js/budget.js`）
- **O（进攻）** = `atk×(1+0.6×crit)×速度轻加权`；**S（生存）** = `hp×(1+def/100)`。
- 归一后 `O/O_ref + S/S_ref ≈ 2.0`，区间 **[1.65, 2.25]**；单轴上限 **1.70**（不许既肉又秒）。
- **稀有度缩放**：进攻 `O_MULT {3:0.72, 4:0.86, 5:1.0}`、生存 `S_MULT {3:0.90, 4:0.95, 5:1.0}`。
- `shape` 可保总预算换形（加攻必减防/血）。

### 装备上限（`js/gear.js`）
- 通用装备分公式：`atk×1 + def×1.2 + hp/8 + crit×800 + spd×2`；**稀有度上限 `{3:170, 4:230, 5:320}`**。
- 专属武器 `exStatsByClass(cls,rarity)`：5★ 满值 / 4★×0.7 / 3★×0.5。

### 敌人预算带（`js/data.js > ENEMIES`）
- 普通怪：`O ≤ 340, S ≤ 5200`；BOSS：`O ≤ 720, S ≤ 14000`。
- 关卡内按等级成长 + 关卡 `mod`（`atkMul/hpMul/healCut/turnLimit/armored…`）缩放。深渊梯度用 `abyss-probe.js` 精调。

## 5. 构建部署实例

上线循环（铁律）：改 `js/*`/`css/*` → bump `index.html` 的 `ASSET_VER` 与所有 `?v=N` → `node scripts/build.js`（先跑 `balance-validate.js` 数值闸门，越界即拒，别用 `--no-validate`）→ commit/push → 轮询线上 `ASSET_VER`（~30–60s 生效）。

### 5.1 容器回滚根因与自愈（2026-07 查明，此前累计回滚 11 次）
- **根因**：云端开发容器闲置会被平台回收，重建时从"环境创建日的快照"（repo@v178）起步——不是 bug，是环境生命周期。远端仓库从未丢数据；丢的只有本地未推送内容和 scratchpad。
- **自愈**：`.claude/hooks/session-start.sh`（SessionStart 钩子）开机自动 fetch+checkout 到远端分支最新+配置 git 身份；护栏=工作区脏/本地不落后时绝不动。自测工具收进 `scripts/devtools/`（smoke/smoke_town/isomock），不再依赖 scratchpad。
- **纪律不变**：一切产物随手 commit+push（回滚保命的根本）；RD key 不入库，回滚后向用户重取。
- **GitHub Pages 部署偶发抽风**："Deployment failed, try again later" 属服务端瞬时故障；**重跑失败 job 会双工件报错，必须用空提交重新触发**。

- **CI**：`.github/workflows/pages.yml` —— push 到 `claude/brown-dust-2-dev-ma6cog` 触发；`validate` job 跑数值平衡校验（Node 20），过了才部署 Pages。任一不过 → 不上线。
- **原生壳（Capacitor）**：`package.json` / `capacitor.config.json` / `scripts/build-web.js`（组装 `www/`）+ `Main.initNative()`（原生下隐藏状态栏 + 锁横屏）。
  - 安卓：`npm run add:android` → `npm run android`（Android Studio 出 APK/AAB）；账号一次性 $25，任意系统可出包。
  - iOS：`npm run add:ios` → `npm run ios`（Xcode，**必须 Mac**）；Apple Developer $99/年。
  - 日常同步：`npm run sync`（= build:web + cap sync）。`android/` `ios/` `www/` 为生成产物，已 `.gitignore`。

## 6. 美术实例

美术方法（锁法A、母图参数、动作、gnorm 组装、闸门）见《说明书·美术章》。本作专属细节：

### 6.0 Retro Diffusion 接入台账（2026-07 起）
- **分工定位**：PixelLab=角色 8 向动画/瓦片集（不动）；**RD=场景物件/建筑/图标**（rd_pro__isometric 256px $0.18/张，质量高一档）；RD 地砖两连败（自带暗边/条纹）→ 地面仍走 PixelLab 瓦片集。
- **调用**：API `POST api.retrodiffusion.ai/v1/inferences`，key 由用户会话内提供（**绝不入库**，存 scratchpad `.rdkey`，容器回滚后要重新向用户索取）；先 `check_cost:true` 免费询价 → **每笔花费先报批**（用户铁律）；`reference_images` 喂已验收件锁风格；`remove_bg:true` 直出透明底。
- **管线**：出图 → 朝向目视（反则 flip 镜像，统一"门脸朝右下、左露山墙"）→ trim → palmap → ditherize amp9 → 五轴（RD 件描边带 ≥9，见 ART_BIBLE）→ 独立复核（工作流双人制）。
- **记账**：测试批 $0.218（木屋✓/草地✗/土路✗）+ 建筑批 $1.26（7 件：6 收货换装上线，well 出图跑题判重出）＝已花 $1.478，余额 $3.628。
- **已知坑**：well 提示词被参照图带偏画成小楼——**小件别喂大建筑参照图**；生成朝向不可控（7 件中 4 件反向），镜像修正零成本，闸门兜底。

### 6.0.5 大图铺底工艺（2026-07 定档，第一章白天村已上线）
- **路线**：整幅场景由用户用 AI 生图（banana=Nano Banana 守设定 / image2 画质氛围强但爱私建+偏夜）出 1792×1024 手绘大图 → 我出提示词+验收（比例/风格/遮挡三项同框判）→ 抠碰撞/遮挡 → 引擎铺底。取代"物件拼贴摆放"路线（拼贴资产转室内/战斗背景用）。
- **定档参数**：引擎 2x **硬放大**（`imageSmoothingEnabled=false` 保笔触，平滑放大会糊）+ 小人 `actorScale 0.6`（=素材 1.2x，门高≈1.15 人高）。

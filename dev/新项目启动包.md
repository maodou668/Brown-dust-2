# 新项目启动包 —— 喂给新会话的第一份文件（AI 纪律根治机制）

> **给未来的我们（用户 & AI）**：这份文件解决一个已被反复验证的问题——
> **AI 会"只读不做"**：规矩写在 CLAUDE.md/说明书里，AI 读了，但在动手那一刻凭临场判断走了捷径
> （实例：管线明写"动画一律 v3"，AI 却擅自用模板动画导致角色掉身份/长辫子，连环返工）。
> **根因**：被动文档不在"决策发生的时刻"触发；靠"AI 记得去查"的规则必然有失手率。
> **根治**：把规则从"读"变成"执行"——用 Claude Code 的 **hooks**（由运行环境在每次工具调用前
> 强制运行守卫脚本，违规调用直接被拒绝，与 AI 的记性/自觉完全无关）+ **产物闸门**（脚本 exit 1）。

---

## 使用方法（新会话拿到本文件后，按序执行，不许跳）

**第 1 步（强制，先于一切开发动作）：安装硬防线。**
把下方【安装脚本】保存为 `install-guardrails.sh` 并执行 `bash install-guardrails.sh`。
它会创建：
- `.claude/settings.json` —— PreToolUse hooks 注册（**随仓库提交，之后每个新会话自动加载，无需再喂任何文件**）
- `scripts/hooks/pretool-guard.js` —— 守卫脚本（规则清单见脚本内注释）

装完必须自测：`bash install-guardrails.sh --test` 全绿才算装好。

**第 2 步：立"经理"和"说明书"。**
- 若是老项目迁移：把《游戏开发说明书》(通用 runbook) + CLAUDE.md(经理/调度台模板) 一并带来。
- 若是全新项目：按说明书《开工填空清单》生成本项目的 CLAUDE.md 与《本作开发档案》。

**第 3 步：开发中的元规则（唯一需要 AI"记住"的一条）：**
> **每当发现一条规矩被违反、而它还不是脚本 —— 立刻把它变成 hook 规则或 exit-1 闸门，再继续干活。**
> 文档层只负责"方法和路由"，**不承担"防 AI 犯错"的职责**；防错永远交给脚本。

---

## 三层防线（架构，供理解）

| 层 | 机制 | 执行者 | 职责 |
|---|---|---|---|
| ① 事前拦截 | `.claude/settings.json` PreToolUse hooks → `pretool-guard.js` | **harness（运行环境）** | 违规**动作**发出即被拒（如用模板动画、绕过校验、未过闸门就 push） |
| ② 产物闸门 | `artgate.js` 等自测脚本 `exit 1` + 通行戳 `.artgate_pass` | 脚本 | 坏**产物**过不了关（脚漂移/串色/掉身份/数值越界） |
| ③ 认知路由 | CLAUDE.md（经理）+ 说明书（部门 runbook） | AI 阅读 | 方法、流程、路由——不再兼任警察 |

已验证的事实：本项目里凡是脚本化的闸门（数值 balance-validate、脚漂移 artgate）**从未失手**；
凡是靠 AI 自觉的规矩（选 v3 还是模板、放大目视）**都失手过**。所以防线只信脚本。

## 安装脚本（自包含，复制即用）

```bash
#!/bin/bash
# install-guardrails.sh —— 一键安装 AI 纪律硬防线（幂等，可重复执行）
# 用法: bash install-guardrails.sh          安装
#       bash install-guardrails.sh --test   安装后自测（7 用例须全 PASS）
set -e
mkdir -p .claude scripts/hooks

# ---------- 守卫脚本 ----------
cat > scripts/hooks/pretool-guard.js <<'GUARD_EOF'
#!/usr/bin/env node
// PreToolUse 硬防线：harness 每次工具调用前强制执行；违规 → deny，调用被拦截。
// 元规则：新踩一个坑 → 在下方加一条规则（每条规则都应对应一次真实返工）。
const { execSync } = require('child_process');
function deny(reason) {
  process.stdout.write(JSON.stringify({ hookSpecificOutput: {
    hookEventName: 'PreToolUse', permissionDecision: 'deny', permissionDecisionReason: reason } }));
  process.exit(0);
}
let raw = ''; try { raw = require('fs').readFileSync(0, 'utf8'); } catch (e) { process.exit(0); }
let input = {}; try { input = JSON.parse(raw || '{}'); } catch (e) { process.exit(0); }
const tool = input.tool_name || '', ti = input.tool_input || {};

// R1 动画一律 v3（模板动画掉身份/长辫子/串配色——已验证的血泪教训）
if (tool === 'mcp__pixellab__animate_character') {
  if (ti.template_animation_id) deny('🚫铁律：禁用 template_animation_id，动画一律 mode="v3"（模板掉身份/串色）。');
  if (ti.mode === 'template' || ti.mode === 'pro') deny('🚫铁律：animate_character 只许 mode="v3"。');
}
if (tool === 'Bash') {
  const cmd = String(ti.command || '');
  // R2 禁绕数值闸门（限定与 build.js 同行，避免误伤"写文档提到该词"）
  if (/build\.js[^\n]*--no-validate|--no-validate[^\n]*build\.js/.test(cmd)) deny('🚫铁律：禁止 --no-validate 绕过数值闸门。');
  // R3 美术 field 变更未过 artgate（缺同批次 .artgate_pass 戳）禁 push
  if (/\bgit\s+push\b/.test(cmd)) {
    try {
      const fake = process.env.GUARD_FAKE_CHANGED;
      const changed = (fake != null ? fake
        : execSync('git diff --name-only @{u}..HEAD 2>/dev/null || true', { encoding: 'utf8' })
      ).split('\n').filter(Boolean);
      const dirs = new Set();
      for (const f of changed) {
        const m = f.match(/^(art\/05_pixellab\/[^/]+_field)\/.*\.png$/);
        if (m && !/\/_artgate_/.test(f)) dirs.add(m[1]);
      }
      const missing = [...dirs].filter(d => !changed.includes(d + '/.artgate_pass'));
      if (missing.length) deny('🚫闸门：field 美术变更未重跑 artgate：\n' + missing.join('\n') +
        '\n先 node scripts/artgate.js <char> 过闸(PASS 写戳)，git add 后再 push。');
    } catch (e) { /* git 不可用则放行，不误伤 */ }
  }
}
process.exit(0);
GUARD_EOF

# ---------- hooks 注册（合并式：已有 settings.json 时不要覆盖，手工合并 hooks 段） ----------
if [ -f .claude/settings.json ]; then
  echo "⚠️ .claude/settings.json 已存在——请手工把下方 hooks 段合并进去（勿整文件覆盖）："
  echo '   PreToolUse: [{matcher:"mcp__pixellab__animate_character"},{matcher:"Bash"}] → node scripts/hooks/pretool-guard.js'
else
cat > .claude/settings.json <<'SET_EOF'
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "mcp__pixellab__animate_character",
        "hooks": [{ "type": "command", "command": "node scripts/hooks/pretool-guard.js", "timeout": 15, "statusMessage": "铁律守卫: 动画一律 v3" }] },
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "node scripts/hooks/pretool-guard.js", "timeout": 15, "statusMessage": "铁律守卫: 闸门检查" }] }
    ]
  }
}
SET_EOF
fi

# ---------- 自测 ----------
if [ "$1" = "--test" ]; then
  pass=0; fail=0
  t(){ # name, expect(deny|allow), json, [env VAR=VAL(可含换行)]
    local out
    out=$(echo "$3" | env "${4:-GUARD_DUMMY=1}" node scripts/hooks/pretool-guard.js)
    if { [ "$2" = deny ] && echo "$out" | grep -q '"deny"'; } || { [ "$2" = allow ] && [ -z "$out" ]; }
    then echo "  ✅ $1"; pass=$((pass+1)); else echo "  ❌ $1 (got: $out)"; fail=$((fail+1)); fi
  }
  t "模板动画→拦" deny '{"tool_name":"mcp__pixellab__animate_character","tool_input":{"template_animation_id":"walking"}}'
  t "v3动画→放" allow '{"tool_name":"mcp__pixellab__animate_character","tool_input":{"mode":"v3"}}'
  t "no-validate→拦" deny '{"tool_name":"Bash","tool_input":{"command":"node build.js --no-validate"}}'
  t "push缺戳→拦" deny '{"tool_name":"Bash","tool_input":{"command":"git push"}}' 'GUARD_FAKE_CHANGED=art/05_pixellab/x_field/idle/s/0.png'
  t "push带戳→放" allow '{"tool_name":"Bash","tool_input":{"command":"git push"}}' 'GUARD_FAKE_CHANGED=art/05_pixellab/x_field/idle/s/0.png
art/05_pixellab/x_field/.artgate_pass'
  t "普通命令→放" allow '{"tool_name":"Bash","tool_input":{"command":"ls"}}'
  echo "结果: $pass PASS / $fail FAIL"; [ $fail -eq 0 ]
else
  echo "✅ 硬防线已安装：.claude/settings.json + scripts/hooks/pretool-guard.js"
  echo "   跑 bash install-guardrails.sh --test 自测；把两个文件 commit 进仓库后，每个新会话自动生效。"
fi
```

## 常见问题

- **本会话装完为什么没生效？** settings 监视器只认会话启动时已存在的配置——装完后**下一个会话**起自动生效（或让用户开一次 `/hooks` 重载）。这正是设计目标：保护所有未来会话。
- **被 hook 拦了怎么办？** 拦截理由里写了正确做法。照做，不要想办法绕——想绕说明该加新规则了。
- **闸门/守卫会不会误伤？** 每条规则都带放行侧自测用例；误伤=规则 bug，修规则，不删防线。
- **artgate 通行戳机制**：`artgate.js` PASS 时在 field 目录写 `.artgate_pass`（FAIL 会删掉它）；push 范围里若有 field png 变更，必须携带同批次的戳变更——基于 git 内容判断，容器回滚/重克隆都不影响。

# 游戏开发说明书（通用 · 跨游戏）

> 这是 **产出②**：与具体游戏解耦的**部门 runbook**。换一款新游戏也照样用——方法论、公式形态、闸门判据、流程步骤都在这。
> 本作的实例值（角色 / 数值 / UI / 剧情 / PixelLab ID 台账 / 构建）见另一份《本作开发档案》，**不要写回本文件**。
> 用法：新游戏先填开头的《开工填空清单》→ 再按 12 个部门章节逐章执行；每章都是「怎么做 + 闸门 + 出什么证据」。
> 凡是本作专有的（锚定角色、主城名、16 人、具体数值）一律用占位符 `<...>` 示意。
>
> ⚠️ **活文档**：本作还没开发完，本说明书就没完。每做出新动作/新机制/新流程/新踩坑，**当场把通用形态回写进对应部门章**（铁律见 `CLAUDE.md §B.6`）。判据：下一个零上下文的人照本章能不能复现。

# 第 0 步 · 安装 AI 纪律硬防线（新项目喂本文件即可，这一步先于一切开发动作）

> **为什么有这一步**：AI 会"只读不做"——规矩写在文档里，AI 读了，动手那一刻仍可能凭临场判断走捷径
> （实例：管线明写动画一律 v3，AI 却擅自用模板动画导致角色掉身份/长辫子，连环返工）。
> **根因**：被动文档不在决策时刻触发。**根治**：规则脚本化，由 Claude Code 的 **hooks 机制**在
> 每次工具调用前强制执行守卫，违规调用直接被拒绝——与 AI 的记性/自觉无关（本项目已实弹拦截过违规调用）。

**执行顺序（新会话不许跳）：**
1. 把下方【安装脚本】存为 `install-guardrails.sh`，执行 `bash install-guardrails.sh`
   → 生成 `.claude/settings.json`（hooks 注册，随仓库提交后**每个新会话自动加载**）+ `scripts/hooks/pretool-guard.js`（守卫）。
2. 自测：`bash install-guardrails.sh --test` 须全 PASS。
3. 用本章末尾的【CLAUDE.md 模板】在项目根目录生成本项目的 `CLAUDE.md`（经理页——Claude Code 自动加载**项目文件夹根目录**的这份文件，所以必须放在新项目里，不能指望别的项目的）。
4. 三样东西（settings.json + 守卫 + CLAUDE.md）commit 进仓库 → 填《开工填空清单》→ 按各章干活。

**三层防线**：⓪ hooks 事前拦截（harness 执行，拦违规动作）→ ① 产物闸门（artgate 等 exit 1 + 通行戳，拦坏产物）→ ② 认知路由（CLAUDE.md + 本说明书，只管方法）。
**元规则（唯一需要 AI 记住的一条）**：*违反了一条还不是脚本的规矩 → 立刻把它加进守卫或做成 exit-1 闸门，再继续干活。*
**维护**：守卫的单一事实源是 `scripts/hooks/pretool-guard.js`；改完跑 `node scripts/make-bootstrap.js` 同步到本章内嵌副本（守卫 R4 会在 push 时强制这个同步）。被拦=照拦截理由改做法；误伤=修规则收窄，不删防线。

## 安装脚本（自包含，复制即用）

```bash
#!/bin/bash
# install-guardrails.sh —— 一键安装 AI 纪律硬防线（幂等）
# 用法: bash install-guardrails.sh          安装
#       bash install-guardrails.sh --test   自测（须全 PASS）
set -e
mkdir -p .claude scripts/hooks

# ---------- 守卫脚本（由 scripts/make-bootstrap.js 自动同步，勿手改此副本） ----------
cat > scripts/hooks/pretool-guard.js <<'GUARD_EOF'
#!/usr/bin/env node
// ============================================================
//  pretool-guard.js —— PreToolUse 硬防线（harness 在每次工具调用前强制执行，
//  与模型记性无关）。stdin 收 {tool_name, tool_input} JSON；
//  违规 → 输出 permissionDecision:"deny" + 原因，调用被直接拦截。
//  规则来源：本项目血泪教训（每条都对应一次真实返工）。
//  配套注册：.claude/settings.json > hooks > PreToolUse（随仓库提交，新会话自动生效）。
// ============================================================
const { execSync } = require('child_process');

function deny(reason) {
  process.stdout.write(JSON.stringify({
    hookSpecificOutput: {
      hookEventName: 'PreToolUse',
      permissionDecision: 'deny',
      permissionDecisionReason: reason,
    },
  }));
  process.exit(0);
}

let raw = '';
try { raw = require('fs').readFileSync(0, 'utf8'); } catch (e) { process.exit(0); }
let input = {};
try { input = JSON.parse(raw || '{}'); } catch (e) { process.exit(0); }
const tool = input.tool_name || '';
const ti = input.tool_input || {};

// ── 规则1：动画禁用模板，一律 v3 ───────────────────────────────
// 教训：walking/breathing-idle 模板在背向掉身份(画成别的角色)、侧向长辫子+串配色
// (Olstein·圣盾 2026-07 连环返工)。v3 锚定角色自己的旋转图，从没出过事。
if (tool === 'mcp__pixellab__animate_character') {
  if (ti.template_animation_id) {
    deny('🚫铁律：动画禁用 template_animation_id（模板会掉身份/长辫子/串色，Olstein·圣盾返工教训）。' +
      '一律 mode="v3" + action_description；idle 用 v3 真呼吸(锁脚提示词)。见说明书·美术 A.3。');
  }
  if (ti.mode === 'template' || ti.mode === 'pro') {
    deny('🚫铁律：animate_character 只许 mode="v3"（template 掉身份；pro 未经用户确认成本）。');
  }
}

// ── 规则5：立绘/半身像禁「正面证件照」——描述必须显式带角度 ─────────
// 教训：2026-07 三套服装半身像里两套出成正面证件照返工（姿势由 description 文字
// 驱动，不写角度词默认正对镜头）。硬性三件套见说明书·美术 §F：身份 + 角度 + 性格 pose。
if (tool === 'mcp__pixellab__create_1_direction_object') {
  const d = String(ti.description || '');
  if (/portrait|bust|half[- ]body|头像|半身/i.test(d)
    && !/three[- ]quarter|3\/4|turned|angled|side view|profile|looking (to|over|aside|into)/i.test(d)) {
    deny('🚫闸门：半身像/立绘的 description 缺角度措辞（three-quarter / head turned / angled…）。' +
      '正面证件照死板禁用——必须带角度 + 按角色性格配 pose。见说明书·美术 §F 硬性三件套。');
  }
}

if (tool === 'Bash') {
  const cmd = String(ti.command || '');

  // ── 规则2：禁止绕过数值闸门（限定"真的在调 build 且带该旗"，避免误伤写文档提到这个词）──
  if (/build\.js[^\n]*--no-validate|--no-validate[^\n]*build\.js/.test(cmd)) {
    deny('🚫铁律：禁止用 --no-validate 绕过数值闸门。先让 balance-validate 过再构建。');
  }

  // ── 规则3：美术 field 变更未过 artgate 禁止 push ───────────────
  // 机制：artgate PASS 时会在该 field 目录写 .artgate_pass 戳；push 范围里若有
  // 某 field 目录的 png 变更，同范围必须也包含该目录的 .artgate_pass 变更
  // （= 改完美术后重新跑过闸门并把戳一起提交）。基于 git 内容，不怕 mtime/回滚。
  if (/\bgit\s+push\b/.test(cmd)) {
    try {
      const fake = process.env.GUARD_FAKE_CHANGED;
      const changed = (fake != null ? fake
        : execSync('git diff --name-only @{u}..HEAD 2>/dev/null || true', { encoding: 'utf8', cwd: process.cwd() })
      ).split('\n').filter(Boolean);
      const dirs = new Set();
      for (const f of changed) {
        const m = f.match(/^(art\/05_pixellab\/[^/]+_field)\/.*\.png$/);
        if (m && !/\/_artgate_/.test(f)) dirs.add(m[1]);
      }
      const missing = [...dirs].filter(d => !changed.includes(d + '/.artgate_pass'));
      if (missing.length) {
        deny('🚫闸门：以下 field 美术有变更但未重跑 artgate（缺同批次的 .artgate_pass 戳）：\n' +
          missing.join('\n') +
          '\n先 `node scripts/artgate.js <char>` 过闸（PASS 会写戳），git add 该目录后再 push。');
      }
      // ── 规则4：守卫规则变更必须同步进说明书第 0 章（内嵌的可移植副本）──────
      // 防"守卫在长大、可移植启动章停在旧版"。同步命令：node scripts/make-bootstrap.js
      if (changed.includes('scripts/hooks/pretool-guard.js')
        && require('fs').existsSync('dev/游戏开发说明书.md')
        && !changed.some(f => /游戏开发说明书\.md$/.test(f))) {
        deny('🚫同步闸门：守卫规则变了但说明书第 0 章（内嵌副本）没同步。\n' +
          '跑 `node scripts/make-bootstrap.js` 再 git add dev/游戏开发说明书.md 后 push。');
      }
    } catch (e) { /* git 不可用等情况放行，不误伤 */ }
  }
}

process.exit(0);
GUARD_EOF

# ---------- hooks 注册（已有 settings.json 时不覆盖，提示手工合并） ----------
if [ -f .claude/settings.json ]; then
  echo "⚠️ .claude/settings.json 已存在——请手工合并 hooks 段（PreToolUse: pixellab 动画 + Bash → node scripts/hooks/pretool-guard.js）"
else
cat > .claude/settings.json <<'SET_EOF'
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "mcp__pixellab__animate_character",
        "hooks": [{ "type": "command", "command": "node scripts/hooks/pretool-guard.js", "timeout": 15, "statusMessage": "铁律守卫: 动画一律 v3" }] },
      { "matcher": "Bash",
        "hooks": [{ "type": "command", "command": "node scripts/hooks/pretool-guard.js", "timeout": 15, "statusMessage": "铁律守卫: 闸门检查" }] }
    ]
  }
}
SET_EOF
fi

# ---------- 自测 ----------
if [ "$1" = "--test" ]; then
  pass=0; fail=0
  t(){ # name, expect(deny|allow), json, [env VAR=VAL(可含换行)]
    local out
    out=$(echo "$3" | env "${4:-GUARD_DUMMY=1}" node scripts/hooks/pretool-guard.js)
    if { [ "$2" = deny ] && echo "$out" | grep -q '"deny"'; } || { [ "$2" = allow ] && [ -z "$out" ]; }
    then echo "  ✅ $1"; pass=$((pass+1)); else echo "  ❌ $1 (got: $out)"; fail=$((fail+1)); fi
  }
  t "模板动画→拦" deny '{"tool_name":"mcp__pixellab__animate_character","tool_input":{"template_animation_id":"walking"}}'
  t "v3动画→放" allow '{"tool_name":"mcp__pixellab__animate_character","tool_input":{"mode":"v3"}}'
  t "绕数值闸门→拦" deny '{"tool_name":"Bash","tool_input":{"command":"node build.js --no-validate"}}'
  t "文档提词→放" allow '{"tool_name":"Bash","tool_input":{"command":"python3 doc.py # 正文提到 --no-validate 但没调 build"}}'
  t "push缺戳→拦" deny '{"tool_name":"Bash","tool_input":{"command":"git push"}}' 'GUARD_FAKE_CHANGED=art/05_pixellab/x_field/idle/s/0.png'
  t "push带戳→放" allow '{"tool_name":"Bash","tool_input":{"command":"git push"}}' 'GUARD_FAKE_CHANGED=art/05_pixellab/x_field/idle/s/0.png
art/05_pixellab/x_field/.artgate_pass'
  if [ -f dev/游戏开发说明书.md ]; then
    t "守卫变更未同步说明书→拦" deny '{"tool_name":"Bash","tool_input":{"command":"git push"}}' 'GUARD_FAKE_CHANGED=scripts/hooks/pretool-guard.js'
    t "守卫变更已同步→放" allow '{"tool_name":"Bash","tool_input":{"command":"git push"}}' 'GUARD_FAKE_CHANGED=scripts/hooks/pretool-guard.js
dev/游戏开发说明书.md'
  fi
  t "普通命令→放" allow '{"tool_name":"Bash","tool_input":{"command":"ls"}}'
  echo "结果: $pass PASS / $fail FAIL"; [ $fail -eq 0 ]
else
  echo "✅ 硬防线已安装：.claude/settings.json + scripts/hooks/pretool-guard.js"
  echo "   跑 bash install-guardrails.sh --test 自测；两文件 commit 进仓库后每个新会话自动生效。"
fi
```

# 部门章节（12 部门 · 通用方法论）

---

## 1. 立项定位

**目标**：把《开工填空清单》的抽象值收敛成可执行的定位文档。

**做法**
- 一句话定位：`<GENRE> + 题材 + 核心卖点`。
- 定「垂直切片」：先做通一条最小可玩链路（1 角色 → 1 战斗 → 1 掉落 → 1 养成），验证核心循环好玩再铺量。
- 明确「模板 vs 内容」边界：脚手架/闸门/引擎可复用，**战斗内核 / 角色关卡数据 / UI 与玩法强绑**，必须按新作重做。

**闸门 / 证据**：一页定位文档 + 垂直切片跑通截图。

---

## 2. 系统玩法

**目标**：把核心循环拆成可实现的系统清单。

**做法**
- 列系统清单：战斗机制、养成线、掉落/经济、进度（关卡/深渊/活动）、抽卡/获取。
- 每个系统标「与数值轴的接口」（消耗什么、产出什么、卡在哪个预算上限）。
- 玩法循环要闭环：产出的资源必须有去处，去处必须再驱动核心循环。

**闸门 / 证据**：端到端 `playtest` 脚本跑通一轮完整循环（见测试闸门章），报告胜率/节奏/资源流是否闭环。

**可复用机制 · 换装/形态轮转 combo**（收集单位有多套"形态/服装"时）
- 单位持一个**形态环**（出战/默认形态排首）；每套只挂自己的技能。战斗中放完当前形态的全部技能 → 下回合（资源够放下一套时）**轮转到下一套**：外观/元素/技能整套换，循环。
- 实现要点：`unit.ring`(有序) + `unit.spent`(本套已放过的技，用 `canUse` 锁住逼玩家攒资源换套) + 回合开始 `maybeRotate(unit)`(两技都放过 && 资源够 → 进环下一格、清 `spent`、清新套冷却)。**渲染层每帧按 `spriteKey(unit)` 取图**，故轮转只需改 `unit.costume/element/skills`，立绘自动跟着换。
- ⚠️ **属性是否随轮转变要早决定**：换 atk/def 安全，换 maxHp 会让血量中途跳变——默认只换外观/元素/技能，属性维持出战形态，要做全属性轮转再单独设计血量归一。

---

## 3. 数值（公式驱动，禁手填）

> 铁律：**数值全部由公式约束，不手填**。任何带数值的新内容（角色/服装/装备/敌人/技能）都必须落在预算内，否则构建与 CI **直接失败、拒绝上线**——防 power creep，防谁都能偷偷压过老内容。
> 一句话：**新内容先用助手函数生成 → 跑 `balance-validate` → 绿了才提交。**

### 3.1 技能：`Balance.make(spec)` 反解威力
不要手填 `power`，只写规格，威力反解：

```js
my_skill: { name:'<技能名>', target:'enemyAll', effect:'damage', sp:4,
            inflict:{ type:'burn', turns:2, power:0.5 }, d: p => `造成 ${pct(p)}% 伤害…` }
```
- `target`：`enemySingle/enemyRow/enemyAll/allySingle/allyAll/self`
- `effect`：`damage/heal/shield/buffAtk/buffDef`
- 附带效果（`inflict` 中毒/灼烧/眩晕/沉默、`pierce` 穿透、`knockback` 击退、`extra` 破防/嘲讽）**都已计价**。
- **判据**：每个实战可达技能的平衡分 `|score-1| ≤ 0.18`；`make()` 出来的天然是 1.00。
- ⚠️ 历史死数据（旧数据结构里已不可达的技能）不计入校验，也别给新角色挂。

### 3.2 属性：双轴预算 O/S 归一
新单位用助手函数生成，不手填 base/grow：

```js
const { base, grow } = Budget.makeCharStats(5, 'mage');                              // 标准 5★ 法师
const { base, grow } = Budget.makeCharStats(5, 'defender', { atk:1.35, def:0.85, hp:0.9 }); // 换形：攻坦
```
- **O（进攻轴）** = `atk × (1+0.6×crit) × 速度轻加权`
- **S（生存轴）** = `hp × (1+def/100)`（等效血量）
- 每单位按 `职业×稀有度` 归一后：**`O/O_ref + S/S_ref ≈ 2.0`**，区间 **[1.65, 2.25]**；**单轴 ≤ 1.70**（不许全堆一轴 → 杜绝「既肉又秒」）。
- `shape` 换形须**保持总预算**：加攻必减防/血。坦克可做成 DPS，但总功率不变。
- 稀有度缩放示例：进攻 `{3:.72, 4:.86, 5:1}`、生存 `{3:.90, 4:.95, 5:1}`（低星也得站得住）。
- 高稀有度服装/皮肤按稀有度缺口自动补偿，保证真有对应档次预算。

### 3.3 装备
- 通用装备：**装备分**（`atk×1 + def×1.2 + hp/8 + crit×800 + spd×2`）不得超该稀有度上限（如 `{3:170, 4:230, 5:320}`）。
- 专属武器：按稀有度缩放（如 5★满值、4★×0.7、3★×0.5），别让低星拿到高星强度。

### 3.4 敌人
- 普通怪 / BOSS 各设 O、S 上限（如普通 `O≤340, S≤5200`；BOSS `O≤720, S≤14000`）。
- 关卡内按等级成长 + 关卡 `mod`（atkMul/hpMul/healCut…）缩放；难度梯度用 probe 脚本精调，改敌人/关卡后**复跑 probe**。

### 3.5 校准新作常数
接新项目时 `balance.js`/`budget.js` 的参考常数（`O_ref/S_ref/CLASS_REF` 等）要**按本作重校准**：先跑 `stat-analyze` 看现有内容分布，再定参考值。

**闸门 / 证据**：见 3.6 与测试闸门章——改任何数值后**必跑 `balance-validate` + 明细 + 战斗自测**并贴结果。

### 3.6 改完必须跑
```bash

node scripts/balance-check.js      # 技能平衡分明细
node scripts/combat-test.js        # 全角色单挑 + 主线不翻车
node scripts/playtest.js           # 端到端：胜率/节奏/连携/难度梯度/站位
# 精调关卡/深渊：ID=<n> N=200 node scripts/stage-probe.js / N=200 node scripts/abyss-probe.js
```

## 4. 代码架构

**源码分层**
- 源码目录 `<js/...>` + `<css/...>` + 入口 `<index.html>`。
- 引擎层可复用：`balance.js`（技能威力）、`budget.js`（双轴预算）、`vfx-framework`（动画/逻辑握手）——按新作重校准常数即可。
- 战斗内核 / 角色关卡数据 / UI 与玩法强绑，须按新作重写。

**build.js 内联**
- `scripts/build.js` 把源码资源**内联进自包含单文件 `<game.html>`**（线上加载它）。

### ⚠️ 外链/内联路径陷阱（血泪教训）
- **外链 CSS 的 `url()` 相对 CSS 目录解析** → 引 `art/` 必须写 `url('../art/...')`；`build.js` 内联进根目录时自动去掉 `../`。
- **自测必测 `index.html`（线上入口），不是内联版 `game.html`**——内联版路径不同会**掩盖 404 路径 bug**（「打开链接没 UI」的根因）。
- 预加载 URL 必须与渲染 URL **逐字一致**（含 `?v=` 版本号），否则重复下载（详见美术章 §资产接入 H.1）。

## 6. 美术（通用 PixelLab 流水线 —— 核心）

> **一个章节管全美术资产**：角色、怪物、地图、UI、特效、立绘。方法论/闸门/风格档案都在这，换游戏**不改方法论，只换风格档案**。

### 6.0 核心信条（做任何美术资产都成立）
1. **一致性靠"锚点派生"**，不靠逐个从零生成。同族资产先做一个精当锚，其余从它派生 → 共享画风。
2. **画风是参数不是常识**。固化成风格档案（6.1），每个 prompt 都套同一份。**没有放之四海的提示词**（柔和动漫禁 `black outline`；复古像素反而要 `bold black outline`）。
3. **闸门先于规模**。每件先过目视/自测闸门 + 人工验收，再做下一件；**绝不批量**。坏母图绝不进下一步。
4. **生成有随机性 → 用兜底阶梯收敛**，不无限 re-roll（一般 ≤2 次不行就换法/兜底）。
5. **归一化是接入前提**。尺寸/锚点/调色不齐必须程序化归一到统一契约再进引擎。
6. **能脚本量化就别靠眼缘**（脚漂移/朝向/接缝/技能配对写成闸门脚本）。
7. ⚠️ **PixelLab 并发约 10 槽硬上限**：塞满后新 job 静默排队/丢失。**一次 fire ≤4 个**，回收再发；产物下载后逐件核对，**缺件单独重发**（别整套重发浪费额度）。出图 ~5–8 分钟，后台 `sleep` 等待再轮询。

### 6.1 风格档案（每个游戏填一份 —— 适配任意游戏的关键）

**A. 通用画风（所有资产共享一份）**

| 维度 | 说明 | 填这里 |
|---|---|---|
| 描边 outline | `selective outline`(柔和) / `single color black outline`(复古) / `lineless` | |
| 明暗 shading | `high detail, soft smooth shading` / `low detail, hard shading`(块状复古) | |
| **风格后缀（固定词串）** | 每个 prompt **结尾固定贴**。柔和动漫=`soft smooth shading, no black outline, clean lineart`；复古像素=`crisp pixel art, bold black outline, limited palette, retro 16-bit` | |
| 调色板 palette | 主色板 / 冷暖基调 / 元素配色规则 | |

**B. 各资产类型参数**：角色/怪物（画布 size、视角、方向数、头身比、动画集）、地图/瓦片（瓦片像素、视角、集结构）、UI（控件清单、边框风格、@1x 尺寸）、特效（帧数、风格词、命中帧法）、立绘/头像（裁切框、输出尺寸）、字体（字号、字符集）。

### 6.2 §A 角色（完整流程 · 已实战）

**A.1 锚点与派生（一致性根基）**
1. **做锚**：代表性角色用 `create_character`（mode v3，按风格档案）精心生成，挑到头身比/画风/骨架满意。**锚定全队上限**。
2. **派生其余**：`create_character_state(character_id=<锚>, edit_description="Transform into: <外观>, <风格后缀>", use_color_palette_from_reference=false)` → 继承骨架/头身比/画风。（这就是「锁法A」一致性做法。）
3. ❌ 不要逐个 `create_character`：v3 忽略 `proportions`，头身比逐个漂移 = 画风不统一头号根因。
4. 外观描述写身份特征（发色/发型/瞳色/服装/配饰/元素宝石/表情）；**别写** `small` / `front view symmetric`（触发大头/对称偏置）。

**A.2 🚦 母图姿势闸门（铁律 · 出母图后、做任何动画前必过）**
动画每帧 frame0 = 母图该向旋转；母图错则整套继承错。先免费看旋转，逐向目视：
- ⚠️ **east/west = 正侧面**：只露一条腿、一条胳膊、侧脸；露第二条腿/正脸=带角度，**不合格**。
- south/north = 正前/正后；斜角 = 真 3/4；头身比/画风与锚一致。
- 不合格 → 锁法A 换 seed 重派生再检测（最多 2–3 次）。⚠️ **侧面单独生成行不通**（漂成正面矮人/糊块），老实重派生母图。

**A.3 动作生成**（`animate_character mode=v3`，镜像省额度：对称向只做一半）
- **idle（循环）**：**一律 v3 真呼吸**，提示词锁脚：`"standing idle, breathing gently and subtly, chest and shoulders rising softly, feet firmly planted, no leg movement"`；背向斜角易抖腿 → 抽腿向单独 re-roll（提示词再加 `legs completely still`）。⚠️ **合成呼吸（垂直压缩上下浮动）只作最后兜底**——用户已判定"非常生硬"，不许当首选。
- ⚠️ **walk/run 必须先建"迈步状态"再循环**：`create_character_state(母图,"mid-stride walking pose…")` 后在该状态做 `walking_cycle`（直接做循环会腿朝别处/转头）。
  - east/west 走路常漂成 3/4 → 在**基础母图**上单独做纯侧面 `walk_side`，归一时覆盖 E/W。
  - 迈步状态偶发把斜角朝向画反 → 靠 A.5 走路朝向闸门兜底。
- **cast/attack（一次性，少数角度）**：描述直接写技能内容（`"casting a blazing inferno"`），元素特效烤进角色帧。**标准：每套服装只配一个施法动作**（一套 2 技共用同一施法）——基础套命名 `cast`，服装套命名 `cast_<元素>`；**不做第二个 cast**（历史 cast_class 已废弃摘除），引擎按「cast_<服装元素> → cast → 首个 cast_*」解析。

**A.4 组装归一**
1. **主归一器**：所有向所有动作统一到固定 bbox + 画布 + 锚点（脚底对齐地线），居中；idle/run 镜像在此用对称表完成。
2. **全员身体高归一**：按身体高（脚→头顶、**排除光环/帽缨**）缩放到统一值 + 高画布；⚠️ 头盔/宽体/光环角色头顶检测易误判 → 提供**显式体高覆盖**。
3. 渲染整幅、脚对齐地线、不裁顶。输出 `<char>_field/` + `manifest.json`，引擎注册 sprite。

**A.5 🚦 走路朝向闸门（组装后必过）**
逐向把 run 与 idle 并排对照，每向 run 朝向必须和 idle 一致。接反/带角度 → 重生成该向 walk-state（换 seed）或水平镜像修正。

**A.6 自测闸门 + 兜底阶梯**
- **脚漂移闸门**：idle 各向脚部逐帧位移全向 ≲1.5px（如 `fd8.js`）。⚠️ **达标≠不抽腿**：背向斜角两腿对称交换、质心不动也会过 → **额外目视背向斜角横条**确认脚钉地（NE/NW/N/E 最易抽腿）。
- **兜底阶梯**：v3 某向抽腿 → **单向 re-roll 1–2 次**（提示词加 `legs completely still`），仍抖才**合成呼吸**（脚钉死 0px，但**观感生硬**——垂直压缩上下浮动，用户不接受当首选，只许单向兜底、不许整套合成）。
- **游戏内配对**：真实场景触发每技能，截图验证动作↔技能↔VFX 不串不缺（`skillcap.js`）。

**A.8 单角色完整清单（复制即用）**
```
[ ] 风格档案已填(6.1)；锚点已做且验收(A.1)
[ ] 锁法A 派生母图(A.1)
[ ] 🚦 母图姿势闸门 逐向合格(A.2)            ← 不过换 seed 重派生
[ ] idle / walk-state→walk / cast 生成(A.3)   ← ≤4 job/批,缺向单独 _v2 重发
[ ] 组装归一(A.4) + east/west 侧面源覆盖
[ ] 🚦 走路朝向闸门 run vs idle 逐向对照(A.5)
[ ] 脚漂移闸门 + 目视背向斜角;抖腿走兜底阶梯(A.6)
[ ] 全员身体高归一;目视全队同框等高(A.4.2)
[ ] 技能两层接入 + 游戏内配对验证(A.7/§E)
[ ] 构建/版本/部署 → 截图发用户验收 → 再做下一个
```

#### A.8 第二套服装 / 皮肤：整套 sprite（已实战 · 换装即换整套小人）
一个角色的第二套服装 = **一整套独立 field sprite**（不是给母套染色）。资产走 §A 全套流程，只是母图从**该角色自有母本**派生（继承头身比/画风），外观描述改成新服装；接入则要引擎能**按激活服装取图**。
- **资产**：`create_character_state(<角色自有母本>, edit_description=<新服装外观>)` → 8 向母图 → 母图姿势闸门 → animate(idle/walk-state→walk/cast) → 下载切帧 → gnorm 组装 → uniformsize → **artgate 脚漂移+朝向闸门**。产出 `<角色>_<服装>_field/`。
- ⚠️ **施法动作跟服装元素走**：cast 描述直接写该服装的技能（如水系服装写"召唤寒冰/水流法阵"），切帧后**把 cast 文件夹/manifest 键命名成 `cast_<元素>`**（如 `cast_water`），好让施法选择器按元素直接命中。
- ⚠️ **idle 源方向要对上**：gnorm 的 idle 默认用 `north-west` 作背向斜角源（NE 镜像它）。若该 state 只生成了 `north-east` idle，gnorm 会退化成 1 帧静态 → 用**合成呼吸兜底**（从对应旋转图、脚钉死、上半身起伏）补 E/W/NE/NW，别留静态。
- 🚫🚫 **动画禁用模板，一律 v3**（血泪教训 · Olstein·圣盾，2026-07）：`breathing-idle`/`walking` 等 `template_animation_id` 模板动画**在背向把身份画成同 group 别的角色、在侧向乱加头发（辫子）+ 串配色（斗篷/裙子变别人的色）**——不只背向坏，**全方向都可能坏**。旋转母图没问题，是模板重定向丢身份。**铁律**：`animate_character` 一律 `mode='v3'`（以角色自己的旋转图当起始帧、锚定身份）；idle 缺向用**合成呼吸**（从旋转图，身份必对、脚 0 漂移），**不要模板 idle**。加西亚之后一直用 v3 没出过事，一换模板就返工。
- 👁️ **脚漂移过 ≠ 通过**：artgate 只量脚，不查"是不是同一个人/有没有长辫子"。**每方向每帧放大目视（≥300px）**确认身份/配色/无多余部件——小缩略图会掩盖辫子、串色、掉身份。
- ⚠️ **服装是"整套部署单位"（BD2 制），别把多套技能混进一场**：出战服装应同时决定 **外观 + 属性 + 元素 + 技能 kit**。若让一个单位同时持有多套服装的技能，会出现"穿 A 套却放 B 套元素的技能、施法动作/立绘对不上"的割裂。取技能池的函数按**当前出战服装**返回（该套 2 技 + 普攻），换套即换整套 kit。
- **引擎接入（按激活服装取图）**：出战服装是"角色展示哪套"的**总开关**——**每一处 sprite 渲染都用同一个 `spriteKey(unit)=有整套 sprite 的服装 ? 服装id : 角色id` 解析**（战斗单位、地图/大世界行走精灵、施法选择器 `cast_<服装元素>`）。任一渲染处漏接就会"战斗换了地图没换"。单位需带上 `costume=activeCostume`（构造函数**白名单拷字段的记得显式加这一项**，否则字段被丢，切换看似无效）。基础服装无独立 sprite → 自动回落角色母套。
- ⚠️ **画布标记别用 HTML 图标字符串**：地图/画布上的节点标记若用 `fillText` 画一个"图标"，而该图标是 `<img src=...>` 之类 HTML 串（本为 DOM 弹窗设计），会被当**文字**画在画面上。画布处单独存一个纯字形(emoji)字段，HTML 图标只给 DOM 用。
- **闸门/证据**：`artgate <角色>_<服装>` 贴输出 + 战斗内截图（换到该服装，确认换的是**整套立绘 + 对应元素施法**，非染色）。

### 6.3 §B 怪物 / BOSS（骨架已就位）
- **本质 = 角色**：`create_character` + `animate_character`，§A 全套方法论/闸门直接复用。
- **一致性策略不同**：怪物形态差异大，不强求全员一锚 → **按阵营/系列各设一锚**（亡灵系一锚、机械系一锚）派生同系怪。
- **动画集按行为定**：idle + move + attack (+ hurt/die)；BOSS 多加大招前摇/阶段切换。
- **体型**：大型 BOSS 用更大 size，归一时**单独一档身体高**。
- 静态场景怪/陷阱可用 `create_map_object`。

### 6.4 §C 地图 / 瓦片（骨架已就位）
- **工具按视角选**：俯视→`create_topdown_tileset`；横版→`create_sidescroller_tileset`；等距→`create_isometric_tile`；高质量→`create_tiles_pro`；道具物件→`create_map_object`（`create_object_state` 出变体/开关态）。
- **风格档案复用**：瓦片同贴风格后缀，保证和角色同画风。
- 🚦 **接缝闸门**：瓦片平铺 2×2/3×3 渲染，目视边缘无缝、无明显重复纹理。
- 🚦 **同框闸门**：地块与角色并排渲染，透视/明暗/像素密度一致（别地块写实、角色卡通）。

### 6.5 §D UI 资产（全套 + 全局接入 · 已实战）
**工具与批量（省额度第一）**
- `create_ui_asset`：面板/按钮/边框/条框/标签页。一次 20–40 generations 出**一张**（非候选制）→ 提示词一次到位。
- `create_1_direction_object`：图标。`size` 决定候选数（≤42→64，≤85→16，≤170→4），一次调用内候选不额外收费。
- 🟢 **批量定法**：`item_descriptions` 数组在**一次调用**里出多个不同图标（如一次出 6 元素图标），省额度关键。别一个图标一次调用。
- **能 CSS 就别生成**：稀有度辉光、凹槽格、三级轻钮、红点/NEW、星级、卡片染色、平滑底辉——纯 CSS 兜。已生成图能复用就复用。

**🚦 像素感闸门（铁律 · 返工教训）**
- ⚠️ **分辨率 = 像素颗粒感**：`create_ui_asset` 出图**越大越"高清"**、颗粒越细 → **不像像素风**（做成 384×512 + `engraved/embossed/filigree/fine detail` → HD 雕花，用户一眼看穿）。
- **定法**：UI 控件尺寸**对齐本套其他件**；提示词写 `chunky pixel art, bold thick, limited palette, hard pixel edges, flat shading, no anti-aliasing`，**别写** `engraved/embossed/filigree/fine/HD/smooth`。
- CSS 侧所有 PixelLab UI 加 `image-rendering: pixelated`。

**九宫格接入（border-image）**
- `border-image: url('../art/...') <slice> fill stretch` + `border-width`；`slice` = 源图四角不拉伸区像素宽。
- **空心框**（稀有度框/头像框）：要透出内容就去掉 `fill` 或让中心透明。
- ⚠️ **居中陷阱**：border-image 边框吃掉内容框 → 里面图标必须 flex 居中 + 尺寸 ≤ 内容框，否则溢出/偏位。

**🚦 路径闸门**（同代码架构章外链/内联陷阱）：外链 `url()` 引 `art/` 写 `../`；**必测 `index.html` 而非内联版**。

**字体全局**
- ⚠️ `body` 的 `font-family` **不传到 `<button>/<input>/<select>/<textarea>`**（表单元素默认不继承）→ 必须显式 `button,input,select,textarea{font-family:inherit}`，否则功能按钮回退系统字。
- 中文像素字用 `pyftsubset` 按**实际用到的字**子集化（~68KB woff2）。⚠️ **缺字逐个回退系统字** → 子集必须覆盖所有 UI 文案，接入后目视确认无回退字形。

**颜色/纹理陷阱（返工）**
- ⚠️ 别用主题色染套框卡空心中心：立绘 `object-fit:contain` 留白，主题色从留白透出成「色条」→ 改暗中性底。
- ⚠️ 别在卡背景铺斜条 `repeating-linear-gradient`（会透上来铺满显脏）→ 平滑径向微辉即可。

**图标可读性**：按**形状**辨识不靠颜色（火=一团火、水=水滴…）；占位 emoji 必须全部换掉。

**接入闸门（部署前）**：无头浏览器（横屏视口，开局跳过剧情）截图前后对比；3× 缩放看边缘锐度/图标居中/无 emoji 泄漏。

### 6.6 §F 立绘 / 头像 / 半身（像素半身双重锁 · 已实战）
两条来源：①用户给的高清立绘 → 程序化**裁切**头像/半身；②PixelLab 生成像素半身像——**别用纯 image2image**，用**双重锁**。
- ❌ **死路**：`create_portrait_character`（纯 image2image）喂低分/带角度像素小人 → **身份丢失**（出通用脸、性别都可能错）。
- ✅ **双重锁**：`create_1_direction_object` **同时给两把锁**——`style_images`（一张**正面母图帧**，锁画风/配色）+ `description`（详细文字）。文字锁「是谁+摆什么」，图锁「什么画风」；一次 4 候选挑最佳、全候选留档。
- 🔑 **description 硬性三件套**（守卫 R5 强制，缺角度词直接拦）：①**身份**（发色/瞳色/服饰）②**角度**（`three-quarter view, head turned slightly, NOT facing straight forward`——**禁正面证件照**，死板；style 锚图是正面帧会把姿势往正面带，必须用文字顶回去）③**性格 pose**（照该角色性格写神态动作：热血少年=侧身远望跃跃欲试、女王=颔首俯视…）。**姿势由 description 完全驱动，不写=默认证件照，不是随机。**
- **尺寸律**：给了 `style_images` 就**不能设 `size`**，输出尺寸 = style 图尺寸；**≥96px 保身份**，style 用正面帧。
- 🚦 **同人闸门**：半身像 + field 小人并排，发色/瞳色/配饰一致。**「带角度」也是挑选的硬维度**——候选里身份贴合但正面的，不许选（本作霜华错选正面候选返工教训）。
- ⚠️ **坑**：①"变全身照"→ 强提示 `head and shoulders only, cropped at chest, NOT full body`；②性别错/糊 → 强化性别词 + `≥96px`；③🔑 **base64 转写腐坏**（手贴几 KB base64 随机坏 `broken data stream`/`Invalid base64`）→ 源图 `quantize` 压到 ~1.5–2KB 再贴，报错重试；**同一份字节流重贴还坏 = 确定性腐坏**，重试原串没用，要**换字节流**：改量化参数或缩小尺寸（如 124→96px）重编码，串更短更稳（本作圣骑士半身像实战：124px 两连败 → 96px 一次过）。

### 6.7 §G 字体 / 其他
像素字体 `create_font`（字号/字符集/风格按风格档案）；一次性资产（loading 图、徽章）按是否需方向/动画选 `create_1_direction_object` / `create_map_object` / `create_ui_asset`。

### 6.8 §H 资产接入与加载工程（跨资产 · 跨游戏通用）
> 生成再好，**加载体验差 = 毁游戏**。这套与画风/引擎无关。

- **H.1 🔑 预加载 URL 与渲染 URL 逐字一致（含 `?v=`）**：只差一个字符（最常见差 `?v=N`）→ 浏览器视作两个资源，预热白做、点界面重下 → 空白等半天。定法：渲染与预加载**共用同一 URL 拼接逻辑**。⚠️ border-image 的 CSS `url()` 通常**不带** `?v` → 对这些资源预加载也用 raw（无 `?v`）才匹配。
- **H.2 全量后台预热**：进主界面即后台（不阻塞首屏）把玩家即将点开的资源拉进缓存（半身像 + idle 帧 + UI 图标 + border-image 贴图）。**清单驱动**：生成资产时同写 `_manifest.json`，预热脚本读它批量 `new Image().src=…`。
- **H.3 转场门控（点开即显、无 pop-in）**：切界面淡出到黑 → 黑屏中渲染新 DOM → 等所有 `<img>` 解码完成（`img.complete`/`decode()`，封顶 ~700ms 兜底）→ 才淡入。兜底超时必设，否则坏图卡死转场。
- **H.4 序列帧用单一全局定时器**：一个全局 `setInterval` 统一推进所有精灵帧索引，别每精灵各开定时器（几十个定时器 = 卡顿+不同步）。帧须已预热。
- **H.5 PNG 瘦身**：无 pngquant 环境用 PIL `img.quantize(256, method=FASTOCTREE)` + `save(optimize=True)`，像素画量化 256 色观感无损、体积省 ~50%。收尾对全部 PNG 跑一遍。
- **H.6 接入闸门**：无头浏览器**冷缓存**走一遍，逐个二级界面应转场淡入即完整、无空白（空白 = 回查 H.1）；3× 缩放看精灵居中/边框锐利/无 emoji 泄漏/动画不抽。

### 移植到新游戏
1. 复制本章 + 通用脚本（归一/自测/接缝/裁切，硬编码路径与 bbox 改成参数）。
2. **填一份新风格档案（6.1）**——唯一需为新游戏定制的东西。
3. 做对应资产类型的锚，跑通一件全流程并验收。
4. 逐件派生量产，方法论与闸门原样不变。靠风格档案四项（描边/明暗/调色/风格后缀）即可从复古像素切到柔和动漫、从 8 向横版切到 4 向俯视，不改流程。

## 8. 剧情演出

**目标**：把作者写的「背景 + 谁说 + 说什么」翻译成引擎可跑的逐句 beat，配立绘/背景/旁白节奏。

### 8.1 喂料模板（作者按此写，工程接）
一场戏 = 一串台词，每句标清**谁说的、配哪张脸、背景在哪**：
```
【背景：<背景代号>】
（旁白）看得见的画面 / 发生了什么。
<角色名>：台词。
<角色名>：（小声）台词。
指挥官：台词。            ← 玩家自己：只有名牌、没有立绘
```
**约定**：
- **旁白**不写名字、居中，只写画面/事件。
- **玩家角色**（如「指挥官」）只有名牌、无立绘。
- **一句一行**（方便逐句配演出）。
- **表情**可选：`<角色名>（生气）：…`（增强层做好后可用）。

### 8.2 技术锚点（工程侧提供给作者）
- **可用角色代号 ↔ 立绘表**：作者用中文名，工程按代号接立绘（本作实例见《本作开发档案》）。
- **反派立绘**：挂敌人代号，格式 `E:<代号>`。
- **可用背景代号**：void（开场/独白/转场）、forest、cave、castle、town、ridge… 需新背景就做。
- **剧情插槽**（已接好触发点，填内容即自动生效）：开场 `prologue`、关卡前 `stage1…N`（布局在 `world.js`）、章节结局、角色羁绊 `side_<代号>`、回放菜单。

### 8.3 ⚠️ 去 AI 味原则
- 台词要**具体、有个性、有潜台词**，避免万金油空话与「作为一个…」腔。
- 旁白只写**能看见的画面**，不解释情绪、不总结主题。
- 一句一事、口语化、留白；避免排比堆砌与过度对仗。
- 名字/设定作者可随时改，工程改数据即可（世界观由作者主导）。

**协作节奏**：作者可**一段一段发**（接一段、部署一段、验一段）或**整章发**批量接。作者只管写，立绘调度/旁白节奏/逐字演出/上线/自测由工程负责。

**闸门 / 证据**：接入后无头截图逐 beat 走查（立绘对得上、背景对、旁白居中、玩家无立绘）。

## 9. VFX（技能特效）

> 技能表现 = **两层模型**（与画风无关的通用结构）。

### 9.1 两层 + 握手
1. **角色层（cast 动画）**：施法动作 + 元素光烤进角色帧（美术章 A.3），贴角色身上。
2. **特效层（独立 burst）**：`create_1_direction_object`（size 64，16 候选）→ 挑（`get_object` 看候选，`select_object_frames` 提升）→ `animate_object`（v3，`frame_count=12` 存 13 帧）→ 下载切帧，打目标身上。
3. **握手（动画↔逻辑同步）**：战斗逻辑瞬时算完且权威；伤害视觉（掉血/飘字）**缓存**，等特效 `impactFrame`（最亮爆发帧）再 flush → 画面与扣血严丝合缝。
4. **标定 impactFrame**：脚本统计每帧亮度/不透明像素峰值，峰值帧即命中帧。
5. **配对/注册表**：每技能 → 一段 cast + 一个 burst；引擎建 `技能id→{cast, burst, 时序, 元素色}` 注册表（`SKILL_VFX`）。素材没到位用程序化 canvas 兜底（握手逻辑相同），到位后**无缝替换零改代码**。

### 9.2 PixelLab 出图标准流程
1. **生成弹体** `create_1_direction_object`（size=64，16 候选），提示词只写**主体 + 风格后缀**。
2. **挑候选** `get_object` 看 16 张挑最贴画风 + 最像爆炸的，`select_object_frames` 提升（免费）；挑不准就下载和立绘并排比。
3. **动画化** `animate_object`（v3，`frame_count=12`→13 帧），动画词强调「亮闪爆发 → 向外扩散 → 干净淡出到烟」（别打旋滞留）。
4. **下载切帧** → `art/.../fx/<effect>/frame_000.png…` + `manifest.json`（`fps`、`frames`、`anchor`、`impactFrame`=亮闪帧、`scale`）。脚本统计亮度峰值定 `impactFrame`。
5. **挂技能** `SKILL_VFX` 加一行：`技能id: { castMs, telegraphMs, star, burst, tint }`（`tint` 配元素色）。多目标技能每个被命中敌人各放一份，伤害在命中帧统一结算。
6. **验证**：bump 版本 → `build.js` → Playwright 截命中帧对比画风 → 提交推送 → 轮询线上 `ASSET_VER`。

### 9.3 素材投放规范（drop-in）
- 帧文件名 `frame_` + 3 位补零（从 000 连续）；透明背景 PNG，正方形画布内容居中。
- `manifest.json`：`fps` 播放帧率、`frames`（须 = 实际 PNG 数）、`anchor`（仅记录，实际锚点由技能时间线指定）、`impactFrame`（命中帧）、`scale`（相对敌人单位宽度缩放）。预警类（如脚下六芒星）无需 impactFrame。

### 9.4 ⚠️ 画风提示词禁忌（血泪教训）
- **柔和/精细画风绝对不要写 `black outline` / `low detailed`** —— 会出粗黑描边复古块状，和柔和立绘对不上（第一版火焰就栽这）。写 `soft smooth shading, fine detailed pixels, no black outline, thin subtle edges, anime fantasy spell effect`，必要时贴本作立绘当 style reference。
- v3 动画倾向「保持物体原位做内部变化」，不会真炸到铺满屏 → 把 `impactFrame` 卡在最亮爆发瞬间扬长避短；需更夸张扩散可用 `end_frame_base64` 插值法。
- MCP 出图 ~5–8 分钟，后台 `sleep` 等待再 `get_object` 轮询，别空转。

**闸门 / 证据**：Playwright 截命中帧对比画风一致；游戏内配对验证动作↔技能↔VFX 不串不缺。

## 12. 上线运营

**做法**
- 严格走上线循环（构建部署章）：bump 版本 → build 数值闸门 → push → 轮询线上 `ASSET_VER`。
- 每次改动收尾**对着原始需求逐条打勾**，自测过了带证据再汇报。
- 上线后回归：CI validate→deploy 门守住，任一不过不上线。
- 内容运营（新角色/活动/关卡）一律先过数值闸门再上；probe 精调后的梯度改动必复跑。
- 资产性能持续维护（PNG 瘦身、预热清单随新资产更新）。

**闸门 / 证据**：线上 `ASSET_VER` 匹配 + 关键路径无头截图 + 需求逐条打勾清单。

# 贯穿一切 · AI 协作层

> 这一层不属于任何单一部门，是所有部门执行时的「怎么做事」纪律。

## 做事协议（每个任务照走）
1. **确认理解**——复述需求，缺的细节**主动问**，别猜。
2. **给方案**——怎么干、产出什么、是否吻合要求，等确认。
3. **开工**。
4. **收尾对着原始需求逐条打勾**。
5. **自测过了、带证据再汇报**。

> 违反 = 返工。历史返工根因：不确认、做完不核对、不自测就汇报、拿单方向证据判全向过、跳管线步骤。

## 硬防线三层（纪律不靠自觉，靠脚本）
| 层 | 机制 | 执行者 | 拦什么 |
|---|---|---|---|
| ① 事前拦截 | `.claude/settings.json` PreToolUse hooks → `pretool-guard.js`（随仓库提交，新会话自动加载） | **harness**（非 AI） | 违规动作本身（模板动画/绕校验/未过闸门 push） |
| ② 产物闸门 | artgate/balance-validate 等 `exit 1` + 通行戳 | 脚本 | 坏产物（抽腿/串色/掉身份/数值越界） |
| ③ 认知路由 | CLAUDE.md + 本说明书 | AI 阅读 | 方法与路由（不兼任警察） |
已验证：脚本化的闸门从未失手；靠 AI 自觉的规矩都失手过。**元规则：违反了一条非脚本规矩 → 立刻脚本化，再继续**。误伤=修规则，不删防线。一键安装/移植：本说明书第 0 章（新项目喂本文件一份即可）。

## 门卫闸门思想
- **写了闸门脚本的，必须跑脚本 + 贴证据（数字/拼图/PASS-FAIL），不许「我看着行」。**
- 美术 sprite 接入前必跑脚漂移闸门并贴原始输出（全向数字 + PASS/FAIL），FAIL 会 `exit 1` 挡死；再逐向目视背向斜角。**走路必先建 walk-state 再 walking_cycle**。
- 数值改动后必跑 `balance-validate` + 对应自测脚本并贴结果。
- 跳过闸门 = 没有交付物可贴 = 一眼露馅。

## 铁律速记
- 只在 `<开发分支>` 开发推送，不开 PR（除非明确要求）。
- 构建必过数值闸门，别用 `--no-validate` 绕。
- 上线循环 bump 版本 → build → push → 轮询 `ASSET_VER`。
- 提交信息按团队约定署名；**任何产物里不出现模型标识**。
- **自测优先于「我觉得」**。
